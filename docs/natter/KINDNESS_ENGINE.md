# Natter — Kindness Engine

## Purpose

The Kindness Engine supports safer, kinder communication while teaching children how to handle difficult interactions.

It should be context-sensitive and coaching-oriented rather than a crude banned-word filter.

## v1 / historical capability

Known work included:

- blocked-word detection;
- coaching / rewrite flow;
- Protected Delivery;
- behavioural signal recording;
- repeated targeting concerns;
- all-caps detection;
- conversation escalation / heat;
- pause behaviour;
- repair-related signals.

## v1.5 direction

Planned richer pattern detection included:

- exclusion;
- coercion;
- all-caps;
- repeated targeting;
- escalating tone;
- context for coaching vs protected delivery vs blocking;
- rewrites;
- time-aware nudges;
- avoiding repeated identical nudges;
- apology / reconnect nudges.

## v2 direction

Future direction included AI-assisted moderation capable of:

- more context-aware intent interpretation;
- longitudinal bullying pattern recognition;
- adaptive coaching;
- richer semantic understanding.

Any AI-assisted moderation should preserve:

- explainable user experience where appropriate;
- data minimisation;
- privacy boundaries;
- strong safeguarding;
- avoidance of simplistic child labelling.

## Intervention ladder

Conceptually prefer the least intrusive safe intervention:

1. allow
2. gentle nudge
3. coaching
4. rewrite
5. Protected Delivery
6. temporary pause
7. block / stronger safety action

This is a product framework, not a fixed algorithm. Severity and safeguarding needs can justify skipping steps.

## Repair matters

The engine should detect and support positive movement after conflict.

A system that only counts harmful events and ignores apology, kindness and reconnection would conflict with Natter's ethos.
